# Prisma — команди

Схема проєкту — multi-file: [`prisma/schema.prisma`](../prisma/schema.prisma) (generator + datasource) і `prisma/models/*.prisma` (по одній моделі на файл). Конфіг — [`prisma7.config.ts`](../prisma7.config.ts) в корені проєкту.

## Перевірка схеми

```bash
npx prisma validate
```
Перевіряє, чи коректний синтаксис у всіх `.prisma`-файлах (враховуючи multi-file schema). Не звертається до бази даних. Запускати після кожної зміни моделей.

```bash
npx prisma format
```
Автоматично вирівнює колонки й форматує `.prisma`-файли (як Prettier, тільки для схеми).

## Міграції (розробка)

```bash
npx prisma migrate dev --name <опис_зміни>
```
Головна команда під час розробки:
1. Порівнює поточну схему з базою даних
2. Створює SQL-файл міграції в `prisma/migrations/`
3. Застосовує її до бази
4. Перегенеровує Prisma Client

Приклад: `npx prisma migrate dev --name init` — перша міграція, `npx prisma migrate dev --name add_status_field` — після додавання нового поля.

```bash
npx prisma migrate reset
```
⚠️ **Видаляє всі дані** — скидає базу, накатує всі міграції заново з нуля. Використовувати тільки на локальній dev-базі, коли дані не шкода втратити (наприклад, схема "розʼїхалась").

```bash
npx prisma migrate status
```
Показує, чи всі міграції застосовані до поточної бази (корисно, коли працюєш у команді й хтось додав нову міграцію).

## Клієнт

```bash
npx prisma generate
```
Генерує/оновлює Prisma Client (типи + методи для запитів) на основі схеми. Виконується автоматично після `migrate dev`, але може знадобитись вручну, якщо просто змінив схему без міграції.

## Робота з базою напряму

```bash
npx prisma studio
```
Відкриває у браузері GUI для перегляду й редагування даних у таблицях — швидка альтернатива pgAdmin для дебагу.

```bash
npx prisma db pull
```
Зворотній напрямок: читає структуру **існуючої** бази і генерує з неї схему. Потрібно тільки якщо хтось змінив структуру БД напряму (SQL, pgAdmin) в обхід Prisma, і треба підтягнути ці зміни в `.prisma`-файли.

```bash
npx prisma db push
```
Застосовує схему до бази **без** створення файлу міграції. Швидко для експериментів/прототипування, але не залишає історії змін — для нормальної розробки краще `migrate dev`.

## Типовий цикл роботи

1. Додав/змінив модель у `prisma/models/*.prisma`
2. `npx prisma validate` — перевірити синтаксис
3. `npx prisma migrate dev --name <опис>` — застосувати до БД і згенерувати клієнт
4. Використовувати в коді через `PrismaService` (`prisma.jobApplication.findMany()` тощо)
